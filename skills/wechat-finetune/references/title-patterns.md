# 公众号标题：四种路子和一条底线

## 底线：钩子 ≠ 标题党

两者的区别不在语气强弱，在**正文兑不兑现**。

判断方法只有一个：把正文读完，回头看标题，它承诺的东西给到了吗？

- 《我把线上 LLM 成本砍了 70%》——正文确实讲了怎么砍、砍在哪、数字哪来的 → **钩子**
- 《我把线上 LLM 成本砍了 70%》——正文只是介绍了几个可能有用的方案，没有真实数字 → **标题党**

同一个标题，是钩子还是标题党，取决于正文。所以拟标题时先问自己：这篇正文最硬的那个东西是什么？标题就承诺那个，别承诺更多。

标题党的代价是复购——读者点进来发现被骗，下次看到这个号就划过去了。公众号是个长期账户。

## 四种路子

拟候选时四种各出一个，让用户在**方向**之间选，而不是在四个同质标题里挑字眼。

### 1. 痛点式：说出读者正在受的苦

读者一眼认出「这说的是我」。适合方案类、踩坑类文章。

- 好：《接了五家大模型之后，我的配置文件失控了》
- 好：《为什么你的 RAG 召回率上不去》
- 弱：《大模型接入的常见问题》——「常见问题」是作者视角的分类，不是读者的痛

痛点要**具体到场景**。「性能问题」不是痛点，「凌晨三点被告警叫醒」是。

### 2. 悬念式：给一个缺口

制造信息差，但不能是虚假的缺口。适合有反转、有非显然结论的文章。

- 好：《这个参数我调了三天，最后发现根本不该调它》
- 好：《所有人都说要加缓存，我们把缓存删了》
- 弱：《一个你不知道的秘密》——缺口太空，读者不知道自己会得到什么

反常识是最好的悬念，但**必须真的反常识**，别为了做悬念把常识说成新知。

### 3. 数字式：把收益量化

数字提供确定性——读者能预估读完的收益。适合有实测数据的文章。

- 好：《13 个代码块，我用一个脚本搞定了公众号排版》
- 好：《省掉 40% token：三处 prompt 改动》
- 弱：《提升效率的若干方法》——「若干」等于没说

数字必须来自正文的真实数据。凑不出真数字就别用这一路。

### 4. 素写式：直接说清楚是什么

不加修辞，靠主题本身的价值吸引对口读者。适合硬核技术文、面向精准人群的号。

- 好：《LiteLLM 多模型网关：从零搭一个统一入口》
- 好：《微信公众号 HTML 的五个粘贴陷阱》
- 弱：《关于网关的一些思考》——「一些思考」把确定的东西说成了不确定的

素写不等于平淡。**信息密度就是它的钩子**——读者一眼看出这篇正好解决他手上的问题。

## 硬约束和常见坑

- **32 字符**是微信的硬限制（超了建草稿会被拒）。每个候选都标好实际字符数。
- **前 12 个字最重要**——手机列表页和转发卡片经常截断，把最抓人的信息放前面。
- **别用读者不认识的术语开头**。「LiteLLM 的 fallback 机制」对没听过 LiteLLM 的人是零信息，划走。要么把术语挪到后半句，要么先给场景。
- **避免全称通用词**：深度解析、最佳实践、全面指南、一文读懂、干货分享。这些词在公众号里已经通货膨胀到零信息量，还会让人联想到内容农场。
- **第一人称通常比第三人称有力**——「我」意味着有真实经历，这正是公众号里稀缺的东西。但号的定位是机构口吻时除外，看画像。

## 输出格式

给用户的候选长这样，路子标出来，字符数标出来，让他知道自己在选什么：

```
1. [痛点式 21字] 接了五家大模型之后，我的配置文件失控了
2. [悬念式 19字] 所有人都在加网关，我们把它删了
3. [数字式 24字] 省掉 40% 的接入代码：一个统一网关的实践
4. [素写式 26字] LiteLLM 多模型网关：从零搭一个统一入口
```

用户选完，把「选了哪一路 + 用户如果补充了理由」记回画像的「标题偏好」——这是这个号口味的长期积累，比任何通用规则都准。
