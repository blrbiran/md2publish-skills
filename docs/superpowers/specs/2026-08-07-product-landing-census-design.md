# 设计：产物落点普查（census-themes.py）

> 2026-08-07 定稿。判据由 `superpowers:brainstorming` 收敛，全部阈值有实测支撑。
>
> 相关文档：判据背景见 `docs/theme-design-lessons.md`（规则 3/6/7/9/11/12/14 与两条判例）；
> 当前状态与基线见 `docs/handoff/handoff.md` 第三、六节。

## 一、要解决什么

`audit-themes.py` 报 0 条不等于主题成立。它查的是「主题文件里有没有**声明**落点」，不查
「产物里这个色实际出现几次」。本仓库已知四次「规范白纸黑字写着、产物里 0 处」——apple-air
的 eyebrow、cyber-neon 的警示 strong、newsprint 的导语、aurora-flow 的次级灰——全部逃过了
现有的每一条检查：审计只看主题文件，自检只看铁律，逐字节回归只看「和上次一样」而上次就是错的。

这一层是目前唯一没有护栏的。本设计把它机械化。

设计过程中的探针又新发现了几处同族缺陷，见第八节，它们都是现有三道检查一条都不报的。

### 覆盖矩阵（本设计的验收标准）

这张表是本脚本存在的理由，也是唯一能防止「脚本跑绿了所以这层有护栏了」这种错觉的东西。
**四个立身缺陷必须全部有档能接**，任何一格是 ✗ 都要在第十节写明为什么不做。

| 立身缺陷 | 出事时的形态 | 由哪一档接 |
|---|---|---|
| newsprint 导语 | 规范写着「全文第一段做导语」，`p_first` 字段当时不存在 | `UNMOUNTED` |
| aurora-flow 次级灰 | 调色板声明，产物 0 处 | `ZERO` / `UNCARRIED` |
| apple-air eyebrow | 唯一强调色在 10 万字符全文里 **1 处**（不是 0） | `NEAR-ZERO` |
| cyber-neon 警示 strong | 规范写着带「注意/警告/不要/会导致」语义的 strong 换色，`strong_alt` 字段当时不存在 | `UNMOUNTED` |

第一版设计只接住了前两个。后两个漏掉的根因写在第四节各自的判据下面——**失败方向与规则 7
记的相反：那次是判据下宽报了大半个库，这次是下窄了，跑到 0 条而缺陷还在。**这正是 lessons
记的 apple-air 模式（「加一条渲染不出来的规范，审计从此闭嘴」）的脚本版。

## 二、三层结构

产物是 `(article.md, theme.json)` 的确定性函数，所以「声明 → 产物」中间还夹着一层
`theme.json`。缺陷可以掉进两个不同的缝里，检出手段完全不同：

| 层 | 比对两侧 | 需要语料 | 抓什么 |
|---|---|---|---|
| **L1** | 主题 `.md` ↔ `theme.json` | 否 | 声明了但机械层没接住；机械层里凭空多出来的色 |
| **L2** | `theme.json` ↔ 产物 HTML | 是 | 落点存在但文章里那个元素不出现；落点全是装饰 |
| **L3** | 主题 `.md` 的语义条款 ↔ `theme.json` 字段 | 否 | 位置性/语义性规范没有机械挂载点 |

L1 和 L3 不依赖语料，任何时候都能跑完。

## 三、文件与职责

```
scripts/theme_lib.py           新建 — 解析纪律的唯一一份
scripts/audit-themes.py        改为 import theme_lib（行为必须零变化）
scripts/census-themes.py       新建 — 九项检查
scripts/test-census-themes.sh  新建 — 变异测试
```

`theme_lib.py` 导出五样：

1. `strip_comments(text)` — 剥 HTML 注释。**必须在查落点之前做**，否则豁免注记里的色值本身会
   变成假落点（`audit-themes.py` 已有此教训）
2. `palette(md_text)` — 解析「色彩系统」段，沿用 audit 的纪律：只取每个 bullet 行的**第一个**
   色值。后面解释里引用的其它色值不算声明
3. `exemptions(md_text, prefix)` — 解析豁免注记。**`prefix` 参数不能省**：它要同时服务
   `audit-ok:` 和 `census-ok:` 两套注记，两个脚本各认自己的那套
4. `theme_pairs()` — 主题名 ↔ theme.json 的**显式对照表**
5. `text_color_count(html, color)` 及其同族计数原语 — 见第六节的三个桶定义。
   抽进来是因为 `background-color:` 含子串 `color:` 这个坑 `audit-themes.py:103` 已经踩过一次，
   不该在 census 里再踩一遍

对照表必须显式且**双向完整性断言**：27 份 `theme.json` 每份都要有对应 `.md`，反之亦然，缺一条
FAIL。不能用正则从文件名推——`13-cyber-neon-v7-edge.theme.json ↔ cyber-neon.md` 推不出来，
而兜底 regex 会在下一个带后缀的主题上静默失配。

**抽取 `theme_lib.py` 是纯重构**：这一步不许加任何新功能，做完必须跑 `test-audit-themes.sh`
到 14 绿，确认 `audit-themes.py` 行为零变化。

## 四、九项检查

### 声明面的定义（L1/L3 共用）

**规范行 = 行里含可机械化实体的行**，即出现 `#hex`、`style=`、或 `属性: 值` 形式的 CSS 声明。
判定**不看行首符号**。带这些实体的行进规范集，纯叙述句自然落选。

第一版按行首符号判（bullet 或表格行），两头都错：

- **漏**：`ink-wash.md:47` 是散文体，却带完整内联样式串
  `<p style="text-align: center; color: #b5432a; ...">□</p>`——货真价实的规范。全库有 **15 行**
  散文体规范带 `style=` 或色值，「## 收尾」节几乎清一色是这种写法。**这是主题库的通用写作
  约定**，不是个别人随手。整类排除等于放弃整个收尾层，而 handoff 第六节第 2 条挂着的
  ink-wash 朱砂印缺陷正在这一层
- **漏**：`cyber-neon.md:36` 是缩进的有序列表项（`  1. `），不是 `-`/`*` 开头

按新轴，`ink-wash.md:8`「像印章落在水墨画上」（比喻，不带色值不带 style）自然落选，
`apple-air.md:51`「代码块刻意素色、无语法高亮」同样落选——它本来就不带实体。

表格行天然满足这条：`editor-slate` 的 GitHub Dark token 表就是表格行声明的，不在「色彩系统」
段里；只扫色彩系统会漏掉它那两个从未兑现的 token 色。

### 判据表

| 档 | 层 | 严重度 | 判据 |
|---|---|---|---|
| `UNCARRIED` | L1 | ERROR | 主题文件规范行里的色值，`theme.json` 里一次都不出现 |
| `INVENTED` | L1 | ERROR | `theme.json` 里的色值，主题文件里任何位置都没有（规则 9：不许自己造色） |
| `INLINE-BLOCK` | L1 | ERROR | **承担定宽的键**样式里有 `display: inline-block` |
| `UNMOUNTED` | L3 | ERROR | 规范行里的语义条款命中关键词，但对应 `theme.json` 字段缺失 |
| `ZERO` | L2 | ERROR | 调色板色在产物里 0 处（已被 `UNCARRIED` 报过的降级为 INFO，见下） |
| `NEAR-ZERO` | L2 | WARN | 调色板色在产物里 1–2 处 |
| `DECOR` | L2 | WARN | 标为强调的色（**只看冒号前的标签**），产物里 `color:` 落点为 0（规则 6） |
| `INVERT` | L2 | INFO | 主强调的文字落点少于副/辅强调，或不足**参照色**文字落点的三分之一 |
| `STALE-NOTE` | — | ERROR | 豁免注记销不到任何发现（见第五节） |

三个术语在此定死，实现时不许自行扩充：

- **承担定宽的键**：定宽由 `md2html.py` 的 `sty(..., boxed=True)` 拼上，实际集合分三段——
  `card`（`md2html.py:324`，**恒 True**）∪ 顶层块级键 `p` `p_first` `h2` `h2_first` `h3`
  `blockquote` `pre` `table` `list_item` `hr`（`:356` 起，`boxed = not card_open`，即**仅无卡片
  主题**）∪ `footer`（`:434`，**恒 True，与有无卡片无关**）。
  `*_html` 片段键和 `h2_text_style` 永不在其中——它们是内层 span，本来就该收缩包裹
  （`washi-spring` 的 `footer_html`、`bauhaus-pop` 与 `arena-charge` 的 `h2_text_style` 都是这种，无害）
- **参照色** = 该主题调色板里**未标强调**，且角色名既不含 `底 / 背景 / 线 / 边 / 卡片 / 面板 /
  纸面 / 块`（这些是装饰面，计数天然高或天然低），也不含 `正文 / 主文字 / 默认文字 / 次级`
  （正文色必然压倒一切强调色，拿它作参照会把全库都报了）
- **强调标签**：一律**只看冒号前的角色标签**，不看破折号后的解释文字——这是
  `audit-themes.py:138-139` 已有的纪律，`theme_lib` 必须继承。全库标签分布：
  `主强调` 15、`副强调` 7、`辅强调` 2、`唯一强调色` 2、`强调` 5、`没有强调色` 1。

  **已知盲区**：6 个主题没有「主强调」锚点（apple-air、coffee-journal、editor-slate、
  ink-wash、newsprint、retro-phosphor），`INVERT` 对它们整档不适用。apple-air 还额外
  参照色集合为空——这是覆盖矩阵里它那格必须靠 `NEAR-ZERO` 而不能靠 `INVERT` 的原因

### `INLINE-BLOCK` 的范围只能照 `boxed=True` 的实际集合定

判例说的是「承担定宽的元素不能是 `inline-block`」，所以判据必须精确复刻 `md2html.py` 里
`boxed=True` 的三段集合，**不能用「主题有没有卡片」这种整体条件近似它**。

第一版就是这么近似的（「无卡片主题的顶层块级键」），两个方向都漏：

- **`card` 键根本不在检查范围**。卡片主题的定宽承担者就是 `card`——20 个卡片主题在这一档下
  等于零覆盖
- **`footer` 被「无卡片」条件屏蔽掉了**。它是 `boxed=True` 无条件，卡片主题在 `footer` 写
  `inline-block` 会静默复现 arena-charge 那个 bug，而检查不响

实测数字本身没错：只看顶层块级键，全库 12 处 `inline-block`，全部落在卡片主题上，
加「无卡片」条件后归零。但这 12→0 证明的是「顶层块 + 无卡片」这个组合窄，不是判据对。
真正中招的 `arena-charge` 是无卡片主题，已在上一轮修好。

这一档在当前库上预期报 0 条。**它有没有牙齿靠变异测试证明，不靠现库有报数**——
三段集合各配一个变异用例（卡片主题的 `card`、无卡片主题的 `h2`、卡片主题的 `footer`）。

### `UNMOUNTED` 的三条匹配纪律

关键词匹配会被规范里的说明文字骗到（`audit-themes.py` 的开发日志记过这件事）。三条纪律缺一不可，
但每一条都有一个必须避开的陷阱——第一版三条全部踩中，直接把这一档要抓的缺陷杀掉了：

1. **只在规范行里搜。** 规范行按上面那条新定义（含可机械化实体），**不按行首符号**
2. **否定只在关键词前后各约 8 字的局部窗口内判**，不做整行布尔判定；
   且**落在引号内（`「」` / `""` / 反引号）的否定词一律不算**——引号里的是被引用的字面串，
   不是作者在否定什么。
   否定词表：`不要` `别` `不用` `建议改用` `无<关键词>`（紧邻组合）

   这条引号护栏不是锦上添花，是 `cyber-neon.md:36` 唯一的活路：那行的「不要」正躺在
   `「注意 / 警告 / 不要 / 会导致」` 这个被引用的枚举里，距离关键词「警示」约 10 字，
   **光靠 8 字窗口挡不住**。
3. **词边界用显式前缀黑名单**（`引`+导语 等），**不用 `\b`**

### 三个陷阱（第一版全踩了）

| 陷阱 | 现场 | 后果 |
|---|---|---|
| **否定词纪律会自杀** | `cyber-neon.md:36`：「原文里带「注意 / 警告 / **不要** / 会导致」这类警示语义的 `strong`，改用 `color: #ff4ba3`」 | 这一档管的正是「注意/警告/不要」语义，**判据靠引用这些词定义自己**，整行判否定必然杀掉自己的靶子。这就是覆盖矩阵里 cyber-neon 那格漏掉的直接原因 |
| **单字「无」是高频词** | 全库到处是「无序列表」「无卡片」「无彩色」「无底」。`mint-breeze.md:44` 的「**无**序前缀」与「步骤类有序列表」在同一行 | 整行判否定会连真条款一起误杀 |
| **CJK 没有 `\b`** | Python 的 `\b` 在汉字之间**永不成立**（汉字都是 `\w`） | 它同时挡住「引导语 ⊃ 导语」（想要）和「褐色序号 ⊃ 序号」「步骤类有序列表 ⊃ 有序列表」（不想要）。两个实现者会写出不同的脚本 |

按新纪律，两条真实误报仍被正确挡住，且都不是靠否定词挡的：

| 误报 | 原文 | 被哪条挡住 |
|---|---|---|
| apple-air → `p_first` | 「不要写 eyebrow **引导语**条款」 | 前缀黑名单（引+导语）；该行虽在 bullet 上但不带色值/style，规范行判定也不收 |
| apple-air → `highlight` | 「代码块刻意素色、无语法高亮」（`apple-air.md:51`，散文行、不带实体） | 规范行判定 |

`ink-wash` 的朱砂印**不再豁免**：`ink-wash.md:47` 带完整内联样式串，按新的规范行定义会被
正确收进来并报 `UNMOUNTED`（该主题 `theme.json` 确无 `footer_html`）。这正是 handoff
第六节第 2 条挂着的活缺陷。

关键词 → 字段的对照表（初版）：

| 关键词 | 要求存在的字段 |
|---|---|
| 导语 / 首段 / 全文第一段 | `p_first` |
| 首个 h2 / 第一个 h2 / 首节标题 | `h2_first` |
| （`警示` 或 `注意` 或 `警告`）与 `strong` **同现**——不是字面整串 | `strong_alt` |
| 印章 / 落款 / 文末装饰 | `footer_html` |
| 提示卡 | `alert` |
| 斑马纹 / 隔行 | `td_alt` |
| 有序列表 / 序号 | `list_prefix_ol_html` |
| 语法高亮 | `highlight` |
| 前缀轮换 | `list_prefix_cycle` |
| 两侧 / 对称饰线 | `h2_suffix_html` |

关键词写成**信号组合**而不是字面整串：第一版写「警示性 strong」，而 `cyber-neon.md:36` 的原文是
「这类警示语义的 `strong`」，字面不匹配——靶子就是这么丢的。

这张表是**人工维护**的，是本设计里最脆的一环。除了三条纪律和变异测试之外，再加一条机械断言
兜住它：

> `md2html.py` docstring 字段表里的每个位置性/语义性字段——`p_first` `h2_first` `strong_alt`
> `footer_html` `alert` `td_alt` `list_prefix_ol_html` `highlight` `list_prefix_cycle`
> `h2_suffix_html`——都必须在本表里有条目，**缺一条 FAIL**。

这样新增 `md2html.py` 字段时忘记同步会立刻响，而不是静默漏检。与第三节 `theme_pairs()`
的双向完整性断言是同一招。

### 为什么阈值不能是绝对计数

实测全库 35 个强调色的产物落点分布，低端三个样本证明绝对阈值这条路是死的：

| 主题 | 色 | 落点 | 为什么不是缺陷 |
|---|---|---|---|
| terracotta-sun | 橄榄绿（副强调） | 8 | 判例里**故意**从 85 压到 8，兑现主题自己的分寸条款 |
| apple-air | 科技蓝（唯一强调色） | 17 | 上一轮刚从 1 修到 17，用户已接受 |
| washi-spring | 灰樱粉 | 23（全是线） | 调色板行自己写着「线色，不作文字色」 |

任何「低于 N 就报」的**通常量级**阈值都会把这三条报成缺陷。所以绝对阈值只能定在**近零**，
其余改用同主题内的相对关系（`INVERT`）和落点性质（`DECOR`）。

**但「近零」不等于「等于零」。** 第一版把绝对阈值收到只剩 `ZERO`（0 处），理由是这张表里
apple-air 有 17 处——**而 17 是修好之后的数字，出事时是 1 处**。拿修复后的值论证「不需要
近零阈值」，等于把靶子挪走再射，覆盖矩阵里 apple-air 那格就是这么漏的。

三个真实低端样本是 8 / 17 / 23，`NEAR-ZERO` 的阈值定在 **1–2 处**：能抓住 apple-air 出事时
的形态，且离最近的样本（8）还有三倍余量，一条都不误伤。定为 WARN 而非 ERROR，因为
「背景色只出现一两次」这类正当形态也落在这个区间，需要豁免注记逐条裁决。

### `INVERT` 为什么定为 INFO 而不是 ERROR

预判它报的 7 条里至少 4 条会裁决为正当设计：主强调偏亮、另有一个「深X」变体承担正文强调，
是被对比度钉住的（规则 11），不是缺陷。

它仍然要进脚本，理由是 **candy-pop 的主次倒置目前没有任何机械手段能重新发现**（handoff
第六节第 3 条，待真机观感定夺）。裁决为正当设计时写下的那行豁免理由，本身就是留档。

## 五、豁免机制

语法（**键是不透明 token，不限于色值**）：

```
<!-- census-ok: INVERT      #f28ba8   主次标签待真机观感定夺，见 handoff 第六节第 3 条 -->
<!-- census-ok: UNMOUNTED   p_first   本主题刻意不做导语，见核心愿景第 2 段 -->
<!-- census-ok: INLINE-BLOCK footer   这里的 inline-block 在内层 span 上 -->
```

每一档的键各不相同，实现时按此表取：

| 档 | 键 |
|---|---|
| `UNCARRIED` `INVENTED` `ZERO` `NEAR-ZERO` `DECOR` `INVERT` | 色值（`#rrggbb`） |
| `UNMOUNTED` | `theme.json` 字段名 |
| `INLINE-BLOCK` | `theme.json` 键名 |

第一版只定义了色值键，于是 `UNMOUNTED` 和 `INLINE-BLOCK` 的发现**一条都销不掉**，
基线「未销掉 = 0」不可达。

用独立前缀 `census-ok:`，**不复用 `audit-ok:`**：两个脚本各有一个叫 `DECOR` 的档
（audit 的是主题文件级，census 的是产物级），共用前缀必然撞名。独立前缀也让现有 14 条
变异测试一行不用动。

三档（ERROR / WARN / INFO）都可豁免。基线是「**未销掉的 = 0 条**」，与 `audit-themes.py`
同一套约定。

配套两条硬规则，否则豁免机制会变成比误报更大的洞：

1. **档名不认识就 FAIL。** 打错档名的注记会静默地什么都不销，这种失败模式看不见。
2. **销不到东西的注记报 `STALE-NOTE`（ERROR）。** 主题改好之后旧注记还挂着，下一个真缺陷
   就会被它盖住。
3. **`STALE-NOTE` 必须按层设门。** 语料缺失时 L2 五档（`ZERO` `NEAR-ZERO` `DECOR` `INVERT`
   及其去重降级）不产生任何发现，那一层的豁免注记会全部变成「销不到东西」，一跑就是一片
   凭空的 ERROR——而这些注记恰恰是设计要求写下来留档的。**某层 SKIP 时，该层的注记一律不判
   stale**，并配一个「无语料 + 带 INVERT 注记」的变异用例。

## 六、报告与运行模式

主报告照 `audit-themes.py` 的样子：按主题分组、一条一行、未销掉的计入退出码。

另加 `--counts <主题>` 模式，输出该主题每个调色板色的落点分解。handoff 第六节说的
「改完必须去数产物」目前每次要现写一段 python，这个模式把它变成一条命令。

三个计数桶按 **CSS 属性名**分，不按视觉直觉分：

| 桶 | 属性 |
|---|---|
| **文字** | `color` |
| **面** | 任何以 `background` 开头的属性（含 `background-image` 里的渐变色标） |
| **线** | 其余全部（`border*` / `box-shadow` / `outline` / …） |

取属性名时必须用 `(?<![-\w])color\s*:` 这类守卫：`background-color:` 含子串 `color:`，
不挡就永远取到底色——`audit-themes.py:103` 已经踩过一次并配了变异用例。
这个计数原语（`text_color_count(html, color)`）抽进 `theme_lib`，两个脚本共用一份。

### 语料缺失与错误处理

- 语料缺失 → **L1/L3 照常出结论，L2 整体 SKIP 并把退出码标红**。沿用 `test-md2html.sh`
  PART B 的约定：静默跳过等于没有护栏
- `md2html.py` 生成失败 / `theme.json` 解析失败 / 对照表不完整 → 该项 FAIL，不静默跳过

### L2 的输入

用 `md2html.py` 从 `theme.json` **现场重新生成**到临时目录再数，不读实验目录里的定稿 HTML。
理由：不依赖 `out/` 那套 `-v1`/`-v5` 混乱命名，也不依赖「定稿与 theme.json 同步」这个假设——
而那个假设失效恰恰是本脚本要报的毛病之一。

语料只需要那一篇 `litellm-multi-provider-gateway.md`（27.9K，仓库外）。频率判断必须用这篇
真实长文：造一篇每种元素各一个的 fixture 会让所有计数都等于 1，对 `INVERT`、`DECOR`、
`NEAR-ZERO` 毫无意义。

**语料路径沿用 `test-md2html.sh:27` 已有的 `MD2HTML_CORPUS` 环境变量**，不另立一个。
两个脚本各定位一次语料迟早会漂。

## 七、变异测试

照 `test-audit-themes.sh` 的范式：每档造一个带已知缺陷的假主题断言报出、再造一个对照断言不报。

三点特别要求：

1. **书写形态先 grep 真实库再造用例。** 漏掉的形态就是漏报——`audit-themes.py` 的 OVER 档
   第一轮 4 个变异全是「行内 code 独占一行」，就漏掉了「代码块与行内 code 同写一行」。
   本脚本已知必须覆盖的形态（每一条都在真实库里有现场）：

   | 形态 | 现场 | 它是哪一档的误报面/漏报面 |
   |---|---|---|
   | 表格行声明色值 | editor-slate 的 GitHub Dark token 表 | UNCARRIED 的漏报面 |
   | **缩进有序条款行**（`  1. `） | `cyber-neon.md:36`，全库唯一带色值的有序行 | UNMOUNTED 的漏报面，也是覆盖矩阵那格的现场 |
   | **散文体带完整 `style=` 的规范** | `ink-wash.md:47` 等 15 行，「## 收尾」节的通用写法 | UNMOUNTED 的漏报面 |
   | 关键词枚举里含否定词 | `cyber-neon.md:36` 的「注意/警告/**不要**/会导致」 | 否定纪律自杀 |
   | 单字「无」在同行 | `mint-breeze.md:44` 的「**无**序前缀」 | 否定纪律误杀 |
   | 子串包含 | 引导语 ⊃ 导语（要挡）；褐色**序号** ⊃ 序号、步骤类**有序列表** ⊃ 有序列表（不要挡） | 词边界两个方向都要断言 |
   | 比喻句（不带实体） | `ink-wash.md:8`「像印章落在水墨画上」 | 规范行判定的误报面 |
   | **同一行把色值当反例引用** | `monochrome-mag.md:15`：「中灰 `#5a5a5a`（…`#767676` 在 `#f2f2f2` 上只有 3.96:1，别用在灰底上）」 | UNCARRIED 取「规范行里的任意色值」而非 palette 的「第一个色值」，这行是它天然的误报面 |
   | 一行两色 | 探针版栽过的角色串行 | 角色标签取值 |
2. **L2 的假产物用受控 fixture 文章造**，重复次数写死，这样 `INVERT` 的倍数关系可断言。
   这与第六节说的「真实库要用真实长文」不冲突：变异测试断言的是逻辑，不是频率合理性
3. **末条对真实库跑**，断言第八节「必须抓到的」那张表**逐条都在报告里**，且加上豁免注记后
   整体归零。**不断言总条数**——总数是第 5 步的产出，把它写死在测试里等于让设计的算术错误
   变成实现的红

## 八、首跑预期

**总条数在实施第 5 步产出，本节不预设。** 第一版在这里写了一个精确的「20 条」，而那个数字
从第四节的判据推不出来（判据修订前实测是 16）——`test-census-themes.sh` 那条「对真实库跑，
断言恰好报出第八节那批」的用例会**红在设计算错上而不是实现上**。按本仓库的历史，那种红最
容易被「改测试迁就它」化解掉。

### 必须抓到的（已独立实证，判据修订不影响）

这几条是验收的硬指标。它们的共同点是**现有三道检查一条都不报**：

| 发现 | 档 | 为什么现有检查抓不到 |
|---|---|---|
| editor-slate `#d2a8ff` `#ffa657` | `UNCARRIED` | GitHub Dark token 表声明 6 色，`theme.json` 的 `highlight` 只兑现 4 个。审计只看主题文件，看到「声明了」就不报 |
| bauhaus-pop `#1e5aa8` | `UNCARRIED` | 规范行写「红 `#be1e2d` 和蓝 `#1e5aa8` 不进代码块」，而该主题调色板里的蓝是 `#005baa`——**引用了一个整个仓库都不存在的色值**。规则 12「规范行里不留旧色值」的新形态：留的不是旧值，是**错值** |
| monochrome-mag `#767676` | `UNCARRIED` | 调色板声明「浅中灰」，组件规范也给了落点（图注、脚注、署名），但 `md2html.py` 根本没有「图注/脚注」这个概念——**声明和落点都在，缺的是机械挂载点**。产物 0 处 |
| gilded-ink `#6a4f1a` `#7a5b1f`、terracotta-sun `#9c8a72` | `INVENTED` | 全在 `highlight` 键上，是执行者为凑对比度现造的色（规则 9）。主题文件里没有，审计永远看不见 |
| blueprint-grid `strong_alt` | `UNMOUNTED` | 规范行写「批注框标题 / 警示性 strong（原文里带"注意、警告、易错"语义的）：`color: #b26a1b`」，`theme.json` 无 `strong_alt`。与 cyber-neon 同族 |

**`UNCARRIED` 三条的修法互不相同**，报告的证据行要能区分开，否则同一档同一严重度会掩盖分歧：

| 形态 | 判别位 | 修法 |
|---|---|---|
| 失步 | 组件规范里**有**落点，`theme.json` 没兑现 | 补 `theme.json` |
| 错值/死色 | 组件规范里**无**落点 | 改主题 `.md`，或按规则 3 从调色板删掉（bauhaus-pop） |
| 无挂载点 | 有落点，但对应元素在 `md2html.py` 字段表里不存在 | 按规则 14 判定加不加字段（monochrome-mag、editor-slate） |

> 这两类——`theme.json` 的 `highlight` 字段根本没有地方可挂这两个色，不是「没兑现」，是「没有

## 九、实施顺序

重构与新功能严格分开，每步都先看着测试红在预期原因上再实现：

1. 抽 `theme_lib.py`，`audit-themes.py` 改 import。**不加任何新功能。**
   验收是**抽取前后对 27 个真实主题跑 `audit-themes.py`、输出逐字节 diff**（一条命令），
   14 绿只当补充。

   **14 绿证明不了行为等价**——已实测：把 `declared_colors` 从「取每行第一个色值」改成
   「取全部色值」（正是第三节说 `theme_lib.palette()` 必须沿用的那条核心纪律），以及删掉
   `NOSPEC` 分支改为静默跳过，**两次定点破坏各跑一遍都是 14 通过 0 失败**。原因是 14 条
   fixture 里没有一条调色板行带两个色值，也没有一条缺「## 色彩系统」段；而第 14 条
   「真实库 0 条」在库本来就干净时是 `0 == 0`，对绝大多数改动无感。
   `palette()` 是 census 四个色值档共同的地基，它静默偏移不会有任何测试响。
   顺带把这两条守卫用例补进 `test-audit-themes.sh`（先红后绿）
2. 写 L1 三档变异用例 → 红 → 实现 → 绿
3. L3 变异用例 → 红 → 实现 → 绿
4. L2 变异用例 → 红 → 实现 → 绿
5. 对真实库跑，**逐条裁决**（条数在这一步才知道，不预设）：写豁免注记，或改主题文件。
   第八节「必须抓到的」那张表要逐条核对确已报出——那是本脚本的验收标准
6. 结论回写 `theme-design-lessons.md`；基线从四条变六条；更新 handoff

**第 5 步的注意事项**：裁决出要改主题文件的，改完必须重生成 `theme.json` 和产物，
`test-md2html.sh` 的 PART B 会变红——那是预期改动不是回归，别反过来改测试迁就它。

## 十、明确不做的

- **不改 `md2html.py`，不加新字段。** 本设计只做检查，不做修复。第八节报出来的缺陷怎么修，
  是第 5 步逐条裁决的事
- **不覆盖内容语义类规范**（哪个数字算「关键」、哪段该升格提示卡）。机械层永远给不了，
  规则 14 已判定这类规范要么交给判断层要么别写
- **不判断颜色好不好看。** 对比度有铁律自检，观感要真机预览。本脚本只回答「声明的东西
  有没有真的出现」
- **`.md` ↔ `theme.json` 的失步只查色值维度。** handoff 第六节第 1 条要求「主题 `.md` 与
  `theme.json` 失步报警」，本设计用 `UNCARRIED` + `INVENTED` 覆盖了色值这一维，
  **字号、间距、前缀符号、`{n}` 模板一概不查**。这个收窄的理由是色值最容易出事、也最好
  机械化；但按本仓库的约定（案例二：改写规范时丢失条款是静默的），显式留档在此，
  不许靠沉默传递
