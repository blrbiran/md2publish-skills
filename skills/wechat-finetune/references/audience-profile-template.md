# 公众号画像模板

存放位置：`./.md2publish/audience-profile.md`（当前工作目录）。

首次运行时由 skill 推断草案、用户确认后生成。之后每次运行读它，只有用户明确要求时才改。**用户手改过的内容优先，不要静默覆盖。**

---

```markdown
# 公众号画像

## 定位
<这个号是做什么的，一两句话。例：面向后端工程师的 LLM 工程实践号，讲踩过的坑和可复用的方案，不做新闻搬运。>

## 目标读者
- 身份：<例：3 年以上后端/平台工程师，正在把 LLM 接进生产系统>
- 已知：<读者默认知道什么，这决定了哪些概念不用解释。例：熟悉 HTTP/API/容器，知道什么是 LLM 和 token>
- 不知道：<读者大概率不知道什么，这决定了哪些必须解释或删掉。例：不了解各家 LLM 厂商的配额差异、不熟悉 LiteLLM 这类网关>
- 处境：<读者什么时候刷到这篇。例：通勤路上、下班后，手机竖屏，随时会被打断>

## 语气
<例：同行之间讲事情的口气，可以有判断和吐槽，不端着；不用「赋能」「抓手」这类词；第二人称「你」而不是「大家」。>

## 署名
author: <公众号署名，≤16 字符>

## 标题偏好
<由 skill 在用户每次选定标题后追加，形成口味记录。例：
- 2026-08-04 选了「痛点式」：《接了 5 家大模型后，我把网关拆了》——用户备注：喜欢有具体数字和第一人称>

## 结尾引导
<结尾要加的固定段落模板；不需要就写「无」。例：
如果你也在做多模型接入，欢迎在留言区说说你踩过哪些坑。>

## 红线
<这个号绝对不写的东西。例：不做厂商对比排名、不写没亲手跑过的方案>
```

---

## 字段怎么用

- **定位 / 目标读者**：判断「这段内容跟读者有没有关系」「这个概念要不要解释」的依据。`已知` 和 `不知道` 两栏是全篇删减决策的锚点，写得越具体，精炼质量越高。
- **处境**：决定段落长度和小标题密度。
- **语气**：改写叙述性文字时的风格约束。
- **署名**：直接进 frontmatter 的 `author`。
- **标题偏好**：拟标题候选时的倾斜方向。这是随使用累积的，不要一次写满。
- **结尾引导**：写「无」就是不加结尾段。
- **红线**：碰到就停下问用户，不要自作主张。
